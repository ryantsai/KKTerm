KKTerm Support

Get help, report a reproducible problem, request a feature, or find the documentation for a KKTerm workflow.

Support for Windows, macOS, and Linux

Keep secrets out of support posts

Never publish passwords, API keys, private keys, access tokens, unredacted host inventories, terminal output, or diagnostic bundles. Start with a sanitized description; maintainers can arrange a safer follow-up if sensitive detail is genuinely required.

Contact and issue reporting

The official support email is publish@ryantsai.com. The public KKTerm issue tracker is also suitable for usage questions, reproducible bugs, compatibility problems, and feature requests that do not contain sensitive information.

Email support Open a public issue

Before opening an issue

  • Install the latest KKTerm release and confirm the problem still occurs.
  • Search existing issues for the same symptom or error message.
  • Include your KKTerm version, operating-system version, CPU architecture, and clear reproduction steps.
  • Describe what you expected and what happened instead.
  • Replace hostnames, usernames, paths, IP addresses, commands, and file contents with safe examples.

Security-sensitive reports

Email publish@ryantsai.com with a non-sensitive summary. Do not post exploit details, credentials, private infrastructure information, or unredacted logs in a public issue, and do not include sensitive material until a safe handling path has been agreed.

Privacy requests

KKTerm keeps app data locally and does not operate a cloud user account, so the project normally has no copy of your saved Connections, terminal content, credentials, or local database. See the privacy choices section for local deletion and third-party provider controls. For a question about KKTerm-controlled web or support records, email publish@ryantsai.com.
