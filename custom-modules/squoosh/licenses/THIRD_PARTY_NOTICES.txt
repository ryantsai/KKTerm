4. Modifications made for this package
-------------------------------------------------------------------------------

The Apache-2.0 license requires that modified files carry prominent notice.
The following changes were made to upstream Squoosh when building this package:

  a) Google Analytics removed.
     src/client/initial-app/index.tsx

     Upstream reports a pageview to Google Analytics (property UA-128752250-1)
     and injects https://www.google-analytics.com/analytics.js on window load.
     A locally installed Module must not contact a third party without consent.
     `window.ga` is retained as an inert no-op because four unrelated UI call
     sites invoke it; removing it outright would raise ReferenceError.
     The packaged output contains no reference to google-analytics.com.

  b) Service-worker access guarded.
     src/client/lazy-app/sw-bridge/index.ts

     KKMod host API v2 replaces `navigator.serviceWorker` with `undefined`.
     Upstream dereferences it with no capability check, which throws during
     startup. Capability guards were added to the three exported entry points.
     No imports or exports changed, so the module graph -- which Squoosh's
     entry-data and client-bundle Rollup plugins depend on -- is unchanged.

  c) PWA and host-configuration artefacts dropped.
     _headers, _redirects, manifest.json, sw.js, serviceworker.js

     These are Netlify directives and PWA install/precache metadata with no
     meaning inside a Module. Note that upstream's _headers requests
     Cross-Origin-Embedder-Policy and Cross-Origin-Opener-Policy in order to
     enable threaded WebAssembly.

  d) Asset URLs rewritten.

     Squoosh emits root-absolute "/c/<hashed-asset>" references. The kkmodule
     protocol resolves a request path against the package root while these
     files live under dist/, so the originals would not resolve. In index.html
     they became "./c/...", and in JavaScript "/dist/c/...".

  e) Inline scripts externalised, source maps omitted.

     The Module CSP is "script-src 'self' 'wasm-unsafe-eval'" with no
     'unsafe-inline'.

  f) KKTerm lifecycle and readiness adapter added.

     A packaged same-origin script reads the current host context, subscribes
     to lifecycle events, and signals `window.KKTerm.ready()` after the usable
     Squoosh UI has mounted. This prevents the host's 15-second startup timeout
     from hiding an otherwise functional editor.

5. Functional note: encoder threading
-------------------------------------------------------------------------------

Squoosh uses threaded WebAssembly for its AVIF, JPEG XL, OxiPNG and WebP2
encoders where the browser is cross-origin isolated. The kkmodule protocol
sends no COOP/COEP headers, so `crossOriginIsolated` is false, SharedArrayBuffer
is unavailable, and the "_mt" codec variants cannot initialise.

This is not a defect in the package. Squoosh feature-detects thread support
(worker-shared/supports-wasm-threads) and falls back to the single-threaded
build of each encoder. Output is identical; encoding those formats is slower.

The unreachable _mt binaries are retained rather than stripped so the upstream
detection paths stay intact and would light up unchanged if the host ever
serves cross-origin isolation headers.
