## Sites

A **Site** is the durable top-level container for Server Rooms and Racks. It is not itself a Connection and owns no live Session or secret. When IT Ops has no Site data, KKTerm keeps an undeletable Default Site so the topology always has a safe parent container.

Open Sites from the add menu beside `itops.title` and choose `itops.racks.addSite`. The New Site dialog explains that a Site can model a region, location, customer, project, or other infrastructure grouping. Enter `itops.sites.nameLabel`; Connection binding is not part of Site creation. The header's shared icon picker customizes the Site icon. Save with `itops.actions.create`.

The left column includes the `itops.title` label/icon and can be resized like the Connection Tree. Dragging its divider tracks the pointer directly, and the chosen width persists when the drag ends. Use the title-bar button immediately before `app.aiAssistant` to hide or show it. Site children are predefined navigation destinations, not stored folders. `itops.navigation.serverRooms` preserves the existing Server Room → Rack topology tree; `itops.tabs.hosts` and `itops.navigation.runHistory` each open their own Site-scoped page. `itops.tasks.heading` is global and therefore appears once outside all Sites.

## Network Maps

`itops.networkMap.nodeKind.generic` adds a general-purpose node beside the built-in device artworks. Generic, Geomap, and Note are grouped together at the bottom of the object browser under `itops.networkMap.nodeCategory.others`. In Node Properties, `itops.networkMap.genericIconLabel` lets that Generic node display any built-in icon without taking on the selected device kind's behavior. A **Deep Link** is an in-app navigation relationship from one KKTerm app element to another; it is not a web URL, external app link, physical Network Link, or binding. `itops.networkMap.deepLinksLabel` attaches Deep Links from a device node to a Connection, Site, Server Room, or Rack Device. Node Properties shows only the saved Deep Link count; activate it to open the compact editor, where each available destination has a direct `itops.networkMap.deepLinkOpenAction` button beside its remove action. A linked node also shows a subtle chain icon and blue count at its right edge; activate it to open the mini list, then choose a destination to open the Connection in Workspace or drill into the corresponding IT Ops topology view. A deleted destination remains listed as `itops.networkMap.deepLinkUnavailable` until its Deep Link is removed from the compact editor.

A **Network Map** is a hand-drawn logical diagram — this is not the physical Site → Server Room → Rack topology drill-down, and the two are kept separate deliberately. Maps are global like IPAM, with an optional Site tag that only labels them. Each map is one canvas of **Network Nodes** and **Network Links**, stored whole.

`itops.networkMap.newMapTitle` creates a map from the top-level map overview. The overview shows every map as a card with an animated preview, its Site tag, and graph counts. Every saved map is also a child row beneath the expandable `itops.networkMap.heading` row in the IT Ops navigator: choose the parent for the card list or a child to open that map directly. As horizontal space becomes available, the overview changes from one column to two, three, and at most four columns. `itops.networkMap.searchPlaceholder` filters this overview across map name, description, Site tag, graph counts, and all saved Network Node, Network Link, and Note metadata; `itops.networkMap.noMatches` appears when nothing matches. Open a card to enter one complete map workspace. The overview header, description, search, and New Map action are removed there; only the current map name is centered in the canvas toolbar. Use the Network Maps parent or another map child in the left navigator to leave or switch the workspace. Switching to another Activity Rail Module also exits the focused workspace immediately, so returning to Network Maps starts from the card list instead of retaining its editor state. The active map toolbar contains only the object-browser pen.

Right-click a map child in the IT Ops navigator for `itops.actions.duplicate`, `itops.actions.delete`, and the final separated `common.properties` command. Each overview card also has one bottom-right `itops.actions.more` menu with `common.properties` and `itops.actions.delete`; there is no exposed delete icon on the card or active-map toolbar. A map has one interaction mode. Network Node resizing uses a 1,000,000-pixel safety ceiling per dimension, so it is effectively unrestricted during normal canvas authoring. Choose the pen icon (`itops.networkMap.paletteLabel`) only to open or close the right-side object browser; closing it gives the canvas the full workspace width without changing canvas behavior. Network Maps use their own soft hardware palette plus `common.customColor`, and black skeuomorphic shells always render on a lightened background; its small status list is an icon-backed radio choice, while the device-type list remains a select only when editing an existing device node. Node Properties shows only `itops.networkMap.interfaceCount_one` / `itops.networkMap.interfaceCount_other`; activate it to open the compact Interfaces editor. Add or edit each named network interface, with an optional documented IP address, through the focused interface dialog (`itops.networkMap.interfaceAddTitle` / `itops.networkMap.interfaceEditTitle`) inside that editor instead of adding rows to Node Properties. Interface addresses are documentation and captions, not lookups into IPAM. Drag from any visible edge dot on one device node to a dot on another device node to link them; each dot accepts either end of the undirected link. The gesture creates one physical member and automatically creates and binds one interface on each endpoint node. A link between two nodes documents that relationship; it does not verify connectivity or define a traffic direction. A link records its name/label (a name for the whole link, such as a circuit id), its medium, and a documented status. Its small medium, status, and display lists use icon-backed radio choices. Link status also controls its animated traffic trace: `itops.networkMap.status.up` is green, `itops.networkMap.status.warning` is orange, and `itops.networkMap.status.down` is red; reduced-motion settings stop the animation. Link Properties shows only the current physical-link count; activate it to open `itops.networkMap.strandEditorTitle`, a compact scrolling grid that keeps large LAGs out of the base dialog. `itops.networkMap.strandAdd` adds a member, automatically creates and binds a new interface on both endpoint nodes, and exposes both interface names plus a free-text speed in one dense row. The speed field keeps common speeds as suggestions, so a 2.5G uplink or an `OC-3` is never blocked by a list. `itops.networkMap.strandDisplayLabel` chooses between `itops.networkMap.strandDisplaySeparate`, which draws every strand and lists each strand's port and speed, and `itops.networkMap.strandDisplayBundle`, which draws one thicker line and groups identical speeds in its readout. The opaque, bordered readout sits above the route so no line crosses its text. Device nodes also record a documented healthy or degraded status. These statuses are operator-authored notes, not live polling. The `itops.networkMap.noteElement` picker item uses the same configure-then-place interaction for a resizable text annotation with the isolated soft background palette, `common.customColor`, and a subtle neutral border. Its Properties dialog includes the `itops.networkMap.noteFormattingLabel` Markdown toolbar plus a sanitized live preview. The saved text remains Markdown source and renders with the same formatting on the canvas. Notes stay above Geomap backgrounds but behind every link and regular Network Node, including while selected. The object-browser `itops.networkMap.importTitle` action seeds a map with a Site's documented Hosts as unlinked nodes; you still draw the links.

The edge readout uses small colored number badges beside compact port and speed values. Entries fill each column top-to-bottom and start a new column after every 12 records, keeping large link groups in a predictable reading order.

A link also records its VLAN membership from the VLANs you have documented: `itops.networkMap.nativeVlanLabel` is the untagged VLAN, and `itops.networkMap.taggedVlanLabel` picks the 802.1Q VLANs it trunks. Any tagged VLAN makes the link a trunk, and a trunk is drawn with a small perpendicular double-tick at its midpoint so trunk-versus-access reads without hovering. The edge label shows `itops.networkMap.vlanAccessChip` for an access link and `itops.networkMap.vlanTrunkChip` for a trunk — the native id plus how many tags ride alongside it. VLANs belong to links only: there is no VLAN node kind, because a VLAN is not a box on the canvas, and VLAN membership is never mapped onto the parallel strands, because a 2×10G LAG carrying six VLANs is two strands and not six.

When a map carries VLANs, `itops.networkMap.vlanLegendHeading` lists them in the Design panel with how many links each one is on. Select one to spotlight it: every link that does not carry that VLAN dims, which answers "where does VLAN 30 actually go?" in one click. The spotlight is a view filter only — it never edits the drawing or verifies connectivity.

A Network Map remains operator-authored documentation and does not poll, monitor, or discover devices. It also does not verify their connectivity.

## Retired Monitor data

The former durable Monitor feature has been removed. Upgrading marks every legacy definition in `itops_automations` obsolete and disabled without changing its saved name, trigger configuration, condition, or action payload. There is no Monitor page, editor, runtime, command, AI tool, or MCP tool, so obsolete rows cannot run. The rows remain available in full database backups and selective IT Ops exports in case their raw data is needed later. Importing a selective IT Ops backup also marks any imported legacy rows obsolete before completing the restore.

## AI Assistant

The shared AI Assistant receives compact IT Ops page context: the current navigator selection, Site names/member counts/transports, loaded rack-topology counts, the Task Library count, recent-run count, and a live-run summary. It does not receive scripts, host output, secrets, or Rack Device details through page context. Ask it operational questions normally; for UI guidance it searches this chapter and can navigate to the IT Ops Module — including a specific Site's Hosts or Run History destination and the global Task Library — or highlight one of the tutorial targets above after you ask to be shown. It can also highlight one specific row using an entity target (`itops.site:` / `itops.host:` / `itops.task:` / `itops.run:` followed by the entity id).

Beyond reading, the assistant's approval-gated `itops_*` tools cover the Module's operations: managing Sites, Server Rooms, Racks, and Rack Devices; creating, importing, scanning, editing, and deleting Hosts; managing VLANs, IP Prefixes, and IP Address Records; reading and editing the Task Library (built-ins stay read-only, and sudo credentials can only be configured in the Task editor); and starting or canceling Batch Runs plus reading Run History reports. Every mutating call goes through the standard tool-approval prompt unless the tool permission mode is Allow All; the assistant can never run a site task silently.

You can paste rough IPAM prose, copied spreadsheet rows, CSV, or notes directly into the assistant. It first reads the current IPAM snapshot and VLAN list, extracts only explicit facts, and shows the normal approval request before applying the typed update. New VLANs, Prefixes, and Address Records are created together through an atomic batch: known duplicates are skipped, while any other invalid record rolls the whole batch back. Existing records are updated by durable id. If the source does not establish a material value such as CIDR, VRF, Site, or whether a line replaces an existing record, the assistant asks instead of guessing. Suggesting documented-free addresses is read-only; workbook reads and active Prefix scans still require approval, and scans must only target networks you are authorized to probe.
