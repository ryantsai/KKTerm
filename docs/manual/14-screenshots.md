## The Screenshots Module

The **Screenshots Module** is an Activity Rail destination (`screenshots.railLabel`, tutorial target `app.activityRailScreenshots`) that captures screenshots into a library folder and lists them newest-first. Settings → General → `settings.activityRail` controls whether the Module appears; it is visible by default.

Passing a PNG, JPEG, GIF, or WebP file path to KKTerm on the command line opens that image directly in the unified editor as an ephemeral source. It does not add the image to the Screenshots library and does not autosave a non-destructive draft. Save rewrites the launched file, Save As writes to the selected destination, and closing the editor discards the in-memory source and any unsaved edits.

Capture actions live in the single-row Module header toolbar and follow `settings.screenshotsCaptureMode` on Windows, macOS, and Linux:

- `screenshots.captureRegion` (tutorial target `screenshots.captureRegion`) — native full-desktop overlay; drag to select a rectangle, Esc cancels. On Windows, the area outside the selection is dimmed while the selected pixels stay clear. Linux prefers the desktop screenshot portal and falls back to an installed desktop selector.
- `screenshots.captureWindow` (tutorial target `screenshots.captureWindow`) — native window picker on Windows/macOS; the Windows picker dims everything outside the highlighted window. On Linux it captures the foreground desktop window after KKTerm minimizes.
- `screenshots.captureFullscreen` (tutorial target `screenshots.captureFullscreen`) — captures the entire virtual desktop across all monitors.

Captures started from the Module header toolbar minimize the KKTerm window out of the way and restore it afterwards. Tray-menu and global-hotkey captures do not minimize KKTerm, so you can include the KKTerm window in the screenshot when it is visible. Capture Mode defaults to `settings.screenshotsCaptureModeBoth`, which saves the image to the library and copies it to the clipboard. Folder-only uses `screenshots.captureSaved`, clipboard-only uses `screenshots.captureCopied`, and Both uses `screenshots.captureSavedAndCopied`; only captures saved to the folder are prepended to the library. When `settings.screenshotsOpenInEditorAfterCapture` is enabled, a saved capture switches to the Screenshots Module and opens the new image in the unified editor. This option is unavailable in clipboard-only mode because that mode creates no library item.

The Module header toolbar also has `screenshots.delay.label`. Its presets are Instant (default), 3, 5, 15, 30, and 60 seconds. The selected delay applies to captures started from the Module header toolbar and to global-hotkey captures. Tray-menu captures remain immediate.

Immediately to the right of Delay, `screenshots.mediaType` switches the three target buttons between `screenshots.mediaImage` and `screenshots.mediaVideo`. Their concise labels are Window, Fullscreen, and Region. Image is selected on launch. Choosing Video checks for FFmpeg before changing modes. On Windows, the missing-dependency sheet can install the Install Helper `ffmpeg` recipe; macOS shows `brew install ffmpeg`, while Linux shows apt, dnf, and pacman examples and provides a recheck action.

Video capture writes directly to the Screenshots folder and appears in the same library as images. Windows supports Window, Fullscreen, and Region using the existing native target picker. macOS and Linux currently support Fullscreen recording; choosing another target reports that platform limit. While recording, a translucent, protected, always-on-top controller sits at the top center of the selected target. Its compact horizontal icon bar can be dragged and provides only `screenshots.video.pause` / `screenshots.video.resume` and `screenshots.video.stop`; it has no target preview and does not appear in recorded frames. On macOS the same two actions and the recording dot appear in a floating pill at the top of the main app window instead of a detached window; it is visible across Modules and disappears when the recording stops. The controller uses the app's existing Tauri/web bundle and adds no second UI runtime. Stopping opens the lightweight `screenshots.video.editorTitle` sheet: the native media preview contains the complete recording frame above a transport row and one resizable timeline clip provided by `@xzdarcy/react-timeline-editor`. Play/Pause and five-second seek actions keep the video and timeline playhead synchronized; the ruler fits the recording duration to the available editor width. Dragging either edge selects a trim range; native text selection is disabled across this editor so timeline labels cannot intercept that gesture. `screenshots.video.exportTrimmed` creates a new copy while preserving the source recording. Recordings are silent in this first slice.

The detached controller's `screenshots.video.pause`, `screenshots.video.resume`, and
`screenshots.video.stop` actions also work while the main window is minimized.

### Library views

The Module header keeps `screenshots.captureWindow`, `screenshots.captureFullscreen`,
and `screenshots.captureRegion` beside `screenshots.delay.label` and
`screenshots.mediaType`. Library view, `screenshots.sort.label`,
`screenshots.group.label`, `common.refresh`, and `screenshots.openFolder` controls
occupy a second row. Capture actions stay visible at the supported 1120px window
width with the Assistant open. Narrower panels show capture icons with the same
accessible names and tooltips; library controls wrap as needed.

The Module header view switch (tutorial target `screenshots.viewSwitch`) offers two layouts, remembered across launches: `screenshots.view.thumbnails` (card grid, default) and `screenshots.view.details` (table with `screenshots.details.type`, `screenshots.details.dimensions`, `screenshots.details.size`, and `screenshots.details.date` columns). The default cosmetic preferences are Date descending for `screenshots.sort.label` and Date for `screenshots.group.label`; both controls remember later changes in `localStorage`. Sort supports Name, Date, or Type in either direction. Group supports Name, Date, Type, Size, Date created, Date modified, Date taken, or Dimensions. Listing is paginated; `screenshots.loadMore` fetches the next page. The library (tutorial target `screenshots.library`) re-reads the folder on every Module activation, so files added or removed outside KKTerm show up on return.

Single-click selects an item, Ctrl/Cmd-click toggles it, and Shift-click extends a range. Dragging an unselected item out of KKTerm transfers that original library file in copy mode; dragging an already-selected item transfers the complete selection in visible order. The thumbnail is only the native drag preview and is never the transferred content. This applies to both image and video items. An image with a `screenshots.draft` badge transfers its last saved source because non-destructive draft layers remain internal until Save flattens them. MP4, WebM, and recorded GIF items carry a compact format badge over their thumbnails; double-clicking one reopens the trim editor. Double-clicking an image opens the unified image viewer/editor. Right-click preserves the current multi-selection when the clicked item is already selected. A `screenshots.draft` badge marks images with autosaved, non-destructive editor layers. Double-clicking that image restores its crop and annotations. If another capture is configured to open directly in the editor, KKTerm flushes the current draft before switching to the new capture. The original image remains unchanged until Save flattens the edits; Save and Don't Save remove the draft, while Rename carries it to the new name and Delete removes it with the image. Open externally, reveal, rename, and delete apply to both media types; image clipboard copy, resize, and conversion appear only for image-only selections. Image clipboard delivery uses the platform's native full-resolution image representations; it never copies the library thumbnail or its data URL. Resize can scale each selected image by the same percentage or use exact dimensions. In exact mode, entering only width or only height makes that dimension exact for every image and derives the other independently from each image's aspect ratio; entering both retains the optional aspect-ratio constraint. Conversion supports PNG, JPEG, WebP, and static GIF output. PNG is lossless, JPEG and WebP use the selected lossy quality, and GIF maps quality to palette-generation accuracy. Resize and conversion save new copies and leave originals unchanged. Delete confirms through the standard confirmation sheet and permanently removes the selected files. The toolbar's icon-only `screenshots.openFolder` and `common.refresh` actions open the library folder and reload it.

The unified dialog uses the shared `Sheet`, opens at 80% of the app window, centers the current filename in its header, and can be resized from its bottom-right handle (`screenshots.editor.resizeDialog`). Its single top toolbar contains previous/next, Save, `screenshots.editor.saveAs`, `screenshots.editor.undo`, `screenshots.menu.copy`, `screenshots.menu.openExternal`, `screenshots.menu.reveal`, delete, pan, annotation tools, annotation color and thickness, and zoom controls. Save uses a floppy-disk icon and overwrites the open library image. Save As uses a stacked floppy-disk icon and opens the native save-file dialog with PNG and JPEG choices regardless of the source format; it writes the flattened edit to the chosen path while leaving the open library source unchanged. `screenshots.menu.copy` copies the currently edited canvas, including unsaved annotations and mosaic regions, to the clipboard. Save, Save As, and copy also have configurable keyboard shortcuts (defaults `Ctrl+S`, `Ctrl+Shift+S`, and `Ctrl+C`) that are rebindable under Settings → Shortcuts → `settings.screenshotsEditorShortcuts`; they act only while the editor dialog is open and not while typing a text annotation. The hand-shaped `screenshots.editor.pan` tool sits immediately before the cursor-shaped `screenshots.editor.select` tool and drags the scrollable image viewport without changing the image. The `screenshots.editor.pencil` tool sits immediately left of `screenshots.editor.arrow` and creates continuous freehand strokes using the current color and thickness; Pencil strokes can be selected to move, restyle, or delete them before saving. The `screenshots.editor.crop` tool sits immediately right of `screenshots.editor.mosaic`; dragging anywhere on the checkerboard stage trims the working canvas to that rectangle, clips/translates existing annotations, and keeps any selected area beyond the image as transparent padding. Crop remains reversible with Undo until Save or Save As flattens the result. Dimensions and file size stay centered in the bottom bar. It starts in Fit mode, measures the available stage, and contains the complete image without scrollbars; `workspace.fileViewer.zoomOut`, `workspace.fileViewer.zoomIn`, and `workspace.fileViewer.fit` provide 25–200% zoom with scrolling at explicit sizes. It can place `screenshots.editor.arrow`, `screenshots.editor.rectangle`, `screenshots.editor.ellipse`, and `screenshots.editor.text` annotations or pixelate a dragged region with `screenshots.editor.mosaic`. Immediately after Crop, a divider starts the annotation styling section: a `screenshots.editor.color` group with six preset swatches (`screenshots.editor.colorRed`, `screenshots.editor.colorOrange`, `screenshots.editor.colorGreen`, `screenshots.editor.colorBlue`, `screenshots.editor.colorBlack`, `screenshots.editor.colorWhite`) plus the shared custom color picker (`common.customColor`), and a `screenshots.editor.strokeWidth` group (`screenshots.editor.strokeThin`, `screenshots.editor.strokeMedium`, `screenshots.editor.strokeThick`) for shape line width. The color applies to pencil strokes, arrows, rectangles, ellipses, and text; thickness applies to pencil strokes and shapes. With `screenshots.editor.text` active, clicking anywhere on the image opens a focused in-place text box at that point; typing shows the text styled with the current color, Escape discards it without closing the editor, and clicking elsewhere or switching tools commits it. Placed annotations stay editable as a temporary layer: the `screenshots.editor.select` tool clicks an annotation to select it, drags it to move, drags its corner or endpoint handles to resize when supported, and Delete removes it; changing the toolbar color or thickness restyles the selected annotation, and double-clicking a text annotation reopens in-place editing. Right-clicking a selected text annotation (or the in-place text cursor) opens a native menu with `screenshots.editor.bold`, `screenshots.editor.italic`, `workspace.fileViewer.fontSize` and `workspace.fileViewer.font` submenus, `common.cut`, `common.copy`, and `common.delete`. Save and Save As flatten the crop and annotation layer into the image; saved files are ordinary flat images with no recoverable layers. The editor ignores clicks outside the dialog and closes only from its top-right Close button or Escape when text entry is not active. Closing or navigating to the previous/next screenshot with edits opens `screenshots.editor.unsavedTitle`, offering Save, `screenshots.editor.dontSave`, or Cancel; Save overwrites before continuing, while Cancel keeps the current screenshot open.

Right-clicking any selected annotation also offers `screenshots.editor.copyElement`. It creates a complete clone slightly down and to the right of the original, selects the clone, and keeps the operation reversible with Undo. The offset stays visually consistent at every zoom level.

### Tray captures and global shortcuts

The tray icon menu groups the same three capture items (`screenshots.captureRegion`, `screenshots.captureWindow`, `screenshots.captureFullscreen`) beneath the `screenshots.railLabel` heading and shows each currently enabled shortcut beside its command. Settings → General → `settings.activityRail` hides this complete tray group when the Screenshots Module is hidden from the Activity Rail. The commands work while the main window is hidden in the tray, and the window stays hidden after the capture. If KKTerm is visible, tray captures and global-shortcut captures leave it visible instead of minimizing it.

Settings → `settings.sectionScreenshots` → `settings.screenshotsShortcuts` defines three system-wide capture hotkeys (defaults `Ctrl+Alt+R` region, `Ctrl+Alt+W` window, `Ctrl+Alt+F` fullscreen). These hotkeys honor the delay selected with `screenshots.delay.label` in the Screenshots Module. On macOS the Settings binding buttons use the Apple modifier names `Control`, `Option`, and `Command`, while stored and registered accelerators keep their canonical modifiers; Windows and Linux keep the canonical display. The same three bindings also appear in Settings → Shortcuts and share one draft, so editing either location updates the other immediately. Click a binding and press a valid key combination to replace and enable it; Escape or focus loss cancels recording. The per-row `settings.shortcutClear` action clears and disables a binding. Registration conflicts with other applications are reported when saving. Settings → Shortcuts also holds a separate `settings.screenshotsEditorShortcuts` group that rebinds the in-app editor's Save (`Ctrl+S`), Save As (`Ctrl+Shift+S`), and `screenshots.menu.copy` (`Ctrl+C`) actions; unlike the global capture hotkeys these are not registered with the OS and only fire while the editor dialog is open.

### Screenshots settings

Settings → `settings.sectionScreenshots` owns the library folder (`settings.screenshotsFolder`, default: the platform Pictures/Screenshots folder), Capture Mode (`settings.screenshotsCaptureMode`: folder, clipboard, or Both by default), the optional `settings.screenshotsOpenInEditorAfterCapture` behavior for saved image captures, image format (`settings.screenshotsFormat`: PNG by default or JPEG), video format (`settings.screenshotsVideoFormat`: H.264 MP4 by default, WebM VP9, or animated GIF), the shared 1–100 image `settings.screenshotsQuality` control, Windows-only DirectX capture acceleration (`settings.useDirectxScreenCapture`), and the global shortcuts. JPEG interprets Quality as lossy image quality. PNG always uses maximum lossless optimization, preserving all pixel values and transparency; Quality is disabled for PNG. This also applies to PNG editor Save/Save As, resized copies, and converted copies. Optimization runs locally and may take longer for large images. MP4 uses H.264, the `veryfast` preset, CRF 23, and broadly compatible YUV 4:2:0 output; WebM uses a real-time VP9 preset; GIF uses 15 fps, a palette pass, and a maximum long edge of 1280 px to control size.

The `settings.screenshotsBorder` subsection controls the automatic capture border. `settings.screenshotsBorderEnabled` is on by default and draws a border inset along the image edges of every new Module or Pane capture — both the saved library file and the clipboard copy — without changing the capture dimensions. While enabled, `settings.screenshotsBorderWidth` (1–64 px, default 1), `settings.screenshotsBorderStyle` (`settings.screenshotsBorderStyleSolid` by default, `settings.screenshotsBorderStyleDashed`, or `settings.screenshotsBorderStyleDotted`), and `settings.screenshotsBorderColor` (default black) customize it. The border applies only to new captures; existing library images are unaffected.

On Windows, the Capture Mode subsection also offers `settings.screenshotsIncludeCursor` (off by default), which draws the mouse pointer at its on-screen position into new region, window, and full-screen captures. For region and window captures the pointer is frozen where it was when the capture started.

## Capture from a Pane

Each workspace surface exposes a screenshot toolbar menu (native Tauri context menu). The menu label is `workspace.takeScreenshot`. Variants:

- `workspace.copyRegion` — capture a selected region and deliver it according to `settings.screenshotsCaptureMode`.
- `workspace.copyEntirePanel` — capture the whole window/Pane using the same delivery setting.
- `workspace.sendRegionToAi` — region capture → AI Assistant input. Status `workspace.sentToAi`.
- `workspace.sendEntirePanelToAi` — whole Pane → AI Assistant input.

When the Screenshots AI tool group (`settings.aiTools.screenshots.label`) is
enabled, the assistant can also work with the saved Module library directly:
list metadata, read one full image, rename/copy/resize/convert/delete captures,
open or reveal files, and start region/window/full-screen captures. Metadata
listing is read-only; image reads and every action that captures, changes, or
opens external state use the normal assistant approval flow.

Tutorial target: `workspace.screenshotMenu`.

Region selection overlay accessible label: `workspace.selectRegion`. Generic noun: `workspace.screenshot`.

Per-surface "screenshot target" labels used in dialog headings:

- SFTP: `sftp.screenshotTarget`
- WebView (URL Connections): `webview.screenshotTarget`; direct toolbar send uses tutorial target `webview.sendToAi`.

Failure: `workspace.screenshotCaptureError`. Outside the Tauri runtime: `workspace.screenshotsRequireRuntime`.

## Capture targets

Pane Region and Entire Window/Panel captures follow `settings.screenshotsCaptureMode`: save to the Screenshots library folder, copy to the clipboard, or both. Saved Pane captures are prepended to the library and honor `settings.screenshotsOpenInEditorAfterCapture`; when enabled, KKTerm switches to the Screenshots Module and opens the capture in the editor. Capture format, quality, and automatic border settings also apply. AI Assistant capture actions remain transient attachments and do not enter the library.

## RDP screenshots

RDP captures use a dedicated typed Tauri command that asks the OS for the visible RDP host bitmap, because the native HWND behind RDP cannot be composited into a normal DOM screenshot. URL Connections use the standard capture path; while `workspace.selectRegion` is active, the URL overlay WebView2 is hidden behind a captured placeholder so the Region controls stay above it. Do not generalise the RDP screenshot code path to other surfaces — see [09-remote-desktop.md](09-remote-desktop.md).

On macOS, RDP renders through the IronRDP canvas path, so RDP and VNC screenshots are cropped from the mounted remote-desktop canvas instead of using the Windows-only OS capture command.
